title: 科研
notes:
  - 科研下载的数据集非常大，首先确认运行服务器和数据服务器是否可以互联，其次确认存储空间是否足够，最后再做目录的确认和数据下载
  - 数据下载首先是代理。下面这个站虽然节点可能不是全绿，但是至少会有可用节点+便宜量大管饱：https://pqjc.site/register?code=fEnIhwFv&cover=sfw
  - 下载的时候要注意先测不同节点对于对方数据服务器的下载速度。再在服务器上建立节点+使用tmux，不要用反向代理转本地端口，这样一来会增加你的I/O压力，在自己使用其他网络活动的时候双方都会受到带宽影响；二来必须保证你的电脑常亮且开启，如果是台式那还好说，笔记本就会比较难受。
  - 下载机制注意：可以使用一些下载技巧来增加下载速度。多路并发+自适应分块策略+httpx支持的头复用，这是目前我用的最多的加速方法。以及退避重试机制；节点有时会不可避免的timeout或者error，那么此时就要依靠退避重试来保持连通性，防止一觉睡醒起来发现睡觉后三十分钟下载就断了，预防高血压，保持血管松弛。以及分块策略的重试机制也需要备上，丢包是很常见的事情，必须要用兜底机制。
  - 到一个新领域怎么做科研？做概要综述、详细综述 -> 看看前沿在做些什么 -> 你感兴趣或者你想钻研的某一个小领域 -> 问题是什么、大家的方案是什么、你的方案是什么 -> 做baseline实验 -> 做你的方法验证、微调 -> 直到你的方法有改进或者优化结果
  - '对于数据集下载策略的详细说明与补充：a.下载位置（数据服务器和运行服务器）、tmux维持。b.多路并发，可以做多次测试来测试并发极限，比如我的服务器就是8个worker和16个worker在有效写盘速度上是无区别的，不要只测下载速度，要测实际写盘速度，因为失败重试的频率是很高的。c.自适应分块。就是计网中的手动大分块实现。我的参数是最小分块-最大分块：256KiB-2MiB，超时、断流后的调整为块大小减半，连续成功 4 块后块大小翻倍。d.HTTPX 连接与请求头复用。使用长期存活的 HTTPX Client，统一配置代理、固定请求头、超时和连接池。连接池上限与多路并发匹配；公共请求头包含 User-Agent、Accept-Encoding: identity，每个请求单独设置 Range 和适用的 If-Range。请求头复用负责保持配置一致；主要性能收益来自 TCP/TLS 连接复用。成功读取完整响应后归还连接，故障连接关闭重建。e.两层退避，网络故障持续恢复。块内重试：最多 8 次，按约 2、4、8、16、30 秒退避，并加入随机抖动；文件级恢复：块内尝试耗尽后，按约 60、120、240、300 秒退避，单次最长 300 秒。若遇到长时间节点失效或者断网，持续等待重试，不设网络故障的总尝试次数上限。f.节点与隧道故障恢复：长时间无有效落盘且健康检查失败时，协调切换订阅节点，重建连接池并重新核对源文件身份后续传。g.断点与校验：每次请求严格核对 HTTP 206、起止偏移、总长度和文件身份。只有完整接收并验证通过的块才追加到 .part，随后 flush、fsync 并保存进度。'
